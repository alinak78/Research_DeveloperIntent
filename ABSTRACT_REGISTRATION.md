**Title:** Whose Intent Counts? Auditing Requirement Violations in LLM-Generated Data-Cleaning Code

**Abstract:**

When language models generate data-cleaning code from underspecified requests, a passing test suite can conceal choices about which records are retained, merged, or excluded. Treating those choices as violations of a developer's implicit intent leaves an accountability question unresolved: whose requirements should define the reference behavior? We develop an audit framework that connects executable constraints to documented policy sources, affected parties, and contested interpretations. The framework retains Intent Violation Rate as a conditional measure of reference-requirement nonconformance, while separately reporting public-test success, unconditional failure, and full compliance. Reanalysis of an existing 49-task algorithm pilot illustrates the measurement gap but does not establish social harms. An executable synthetic example shows how optional-field deletion can pass basic normalization tests while violating a retention rule. We specify a source-grounded audit of public-service intake transformations comparing ambiguous requests, explicit policies, and clarification conditions. The central contribution is a method for making requirement authority and record-exclusion assumptions inspectable, rather than equating hidden-test success with fairness. The planned domain audit will test the framework's usefulness and limits; its results are not yet available.

**Focus areas:** Evaluations and evaluation practices; Normative foundations and implications.

**Keywords:** AI-assisted programming; sociotechnical evaluation; requirement provenance; data cleaning; record retention; accountability; clarification.
